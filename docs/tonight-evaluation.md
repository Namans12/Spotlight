# Tonight ranking evaluation

Run `npm run evaluate:tonight` to compare the existing Tonight ranking with the optional-feedback ranking. Both use the same candidates and filters; the baseline has no feedback weights. Candidates already dismissed are excluded from both inputs. The script reports reciprocal rank for the first hand-labelled relevant title and mean reciprocal rank (MRR) across four examples.

These examples are synthetic regression probes, constructed to check that a negative genre signal changes ordering and that watched or unavailable feedback does not penalize a genre. They are not independent user judgments, production traffic, or evidence of improved satisfaction. The current expected MRR is 0.75 for the baseline and 1.00 with feedback on these four constructed examples.

On 13 November 2026, a signed-in browser session on the deployed site generated live catalogue options, saved one previously unsaved option, verified it in the watchlist after reload, and removed it again; the removal persisted after reload. This is a smoke test of one save path, not an evaluation of recommendation quality, all filters, or a user study.

On the same date, a live India-filtered session showed Netflix subscription matches; selecting Apple TV Store without paid offers produced no matches, while enabling rentals and purchases returned separately labelled rent/buy offers. Session feedback hid an option and could be cleared. These checks demonstrate the tested cases only; provider data can change and the checks are not judgments of recommendation relevance.

Each case also reports precision among up to the first three eligible options, the fraction of labelled relevant titles present in the eligible set, and the eligible count. The paired comparison rejects mismatched or duplicate eligible identities. Keys distinguish movies from TV shows. Coverage is null when no relevant titles have been labelled; a missing label is not evidence of a dislike.

Feedback stays in the current page session and is not sent to a server. A meaningful quality comparison would require a larger independently labelled, representative set or an explicitly opt-in user study, with the same eligibility constraints for both rankings and attention to coverage as well as ranking quality.

One possible external research source is [MovieLens latest-small](https://files.grouplens.org/datasets/movielens/ml-latest-small-README.html), which contains historical, independently supplied movie ratings and TMDB links. Its licence prohibits commercial or revenue-bearing use without permission, and GroupLens describes it as a changing development dataset unsuitable for shared research results. Ratings are not Tonight's session feedback, omit TV and current India availability, and are affected by what people chose to rate. The dataset has not been imported or used here; assess the project's intended use and applicable licence before any experiment, and do not treat such an experiment as Spotlight user satisfaction.

For a separately prepared local dataset, run `npm run evaluate:tonight -- --input path/to/cases.json`. A synthetic example is available at `docs/tonight-evaluation-example.json`. The file is read locally; the evaluator makes no network requests and sends no feedback or labels to a server. Do not include personal or identifying information in shared fixtures.

The offline report includes a paired macro-average for each metric and the number of cases contributing to it. A case contributes only when both rankings have that metric; missing values are never treated as zero. Precision is undefined when no candidate is eligible; relevant coverage still reports zero when relevant labels exist but no relevant candidate is eligible. Reciprocal rank can still be based on partial judgments, and its case count does not establish representativeness or statistical significance.

The JSON object contains a nonempty `cases` array. Each case has `name`, `filters` (the Tonight filter fields), `candidates` (title objects with positive numeric `id`, `mediaType`, `title`, `originalLanguage`, `releaseDate`, and optional `genres` and `runtime`), `offers` keyed by `movie:<id>` or `tv:<id>`, `feedback` keyed the same way, `duelWeights`, and `judgments` mapping candidate keys to `relevant` or `not_relevant`. Empty objects are valid for the last four fields. Offer types must be subscription, free, ads, rent or buy; a missing offer means unknown. Feedback entries use `{ "kind": "not_interested" | "already_watched" | "not_available", "genres": [...] }`.

The evaluator applies the same filters, offer constraints, Duel weights and dismissed-title exclusions to both rankings, then applies feedback weights only to the updated ranking. It rejects duplicate identities and malformed inputs. Omitted judgments remain unjudged: full top-three precision is null when any eligible title lacks a judgment, and `topThree.judgedPrecision` describes only the judged titles shown. Reciprocal rank is null when no relevant titles are labelled; with partial judgments it is based only on the labels provided, not proof that higher unjudged titles are irrelevant. These reports require representative, independent labels to support any product-quality conclusion.

To compare against an existing recommender rather than Tonight without feedback, provide `baselineOrder` in every case: an array of every candidate's `movie:<id>` or `tv:<id>` key, in the original recommender's order. The evaluator rejects missing, repeated or extra identities, removes the same dismissed and ineligible candidates from both rankings, and labels the report `provided_order`. It does not reconstruct the old recommender's order or collect production feedback. Do not mix provided orders and the default baseline in one report, and do not treat a synthetic ordering as evidence of real-world improvement.

Try the synthetic format with `npm run evaluate:tonight -- --input docs/tonight-evaluation-baseline-example.json`.
